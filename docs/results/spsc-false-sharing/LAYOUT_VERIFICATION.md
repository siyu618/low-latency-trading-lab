# Experiment 02 Phase 3A — runtime cursor-layout verification

Every measured repetition of the canonical matrix, with the cursor
addresses and cache-line indices that were **measured on the very queue
object that repetition timed**, outside the timed interval.

- host-reported cache-line size: **128 bytes**
- compile-time layout assumption: **128 bytes**
- `same_line` rows MUST show `head_line == tail_line`
- `separated` rows MUST show `head_line != tail_line`

The compile-time alignment creates the intended CANDIDATE layout. What
decides whether the controls hold is the MEASURED address relationship
below, read against the host's reported line size. If the host had
reported a line size larger than the compile-time assumption the benchmark
would have exited non-zero **before timing anything** and this file would
not exist: past that size the compile-time alignment can no longer keep
the `separated` control's two blocks in distinct real blocks, so the
control could not be justified by construction.

## Equal footprint (Phase 3A.1)

Cursor placement is the ONLY program-layout treatment, so the payload array
must keep the same RELATIVE offset from the object base in both variants —
otherwise the object's internal layout shifts with cursor placement and the
comparison changes two things at once. Each row below lists the object size
and payload offset the two
layouts' processes reported, measured on the objects they actually ran.
They MUST agree. The benchmark refuses to time a cell that fails this, so
these columns are a re-check of already-gated evidence.

| message bytes | capacity | object size | payload offset |
|---|---|---|---|
| 8 | 1024 | 8448 | 256 |
| 8 | 4096 | 33024 | 256 |
| 8 | 65536 | 524544 | 256 |
| 32 | 1024 | 33024 | 256 |
| 32 | 4096 | 131328 | 256 |
| 32 | 65536 | 2097408 | 256 |
| 64 | 1024 | 65792 | 256 |
| 64 | 4096 | 262400 | 256 |
| 64 | 65536 | 4194560 | 256 |

Both cursor policies occupy `2 * 128 = 256` bytes, asserted at compile
time in `include/spsc_cursor_layout_ring_buffer.h`. The `same_line` policy
keeps BOTH cursors in the FIRST line and reserves an inert second line
purely to match that footprint; the reserved line is never read or written
by `try_push`/`try_pop`/`empty`.
