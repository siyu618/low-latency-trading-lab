# Experiment 02 Phase 4 — SPSC tail latency / jitter: exact invocations.
#
# repo HEAD: 6924992bac27510997a4497c23ad126527063f61
# binary: build-spsc-tail/spsc_tail_latency_bench
# messages=10000000 settling_prefix=100000 sample_interval=1021
# reps=5 warmup=1 sessions=4
# expected_samples_per_repetition=9696
#
# THE MEASURED QUANTITY is producer_ready -> consumer_received: stamped
# immediately before the producer's try_push retry loop and immediately
# after a successful try_pop, before any validation. It INCLUDES the
# producer's retry/backpressure wait, the queue's release/acquire
# synchronization, the payload copy, the consumer's empty-retry loop and
# both clock reads. It is NOT pure queue residence time and NOT a
# per-call queue cost.
#
# THE QUEUE is the SEPARATED-CURSOR BASELINE only. The Phase-3B cached
# variant, the mutex queue and the Phase-3A same-line layout are NOT in
# this matrix. Phase-4 absolute values must NOT be compared with Phase-2
# or Phase-3 absolute values: the message shapes are 16/32/64, not 8/32/64.
#
# THE SESSION ORDER balances temporal position (forward, reverse, forward,
# reverse). It does NOT eliminate scheduler variation, core migration or
# DVFS drift, and must not be described as doing so.
#
# --sample-interval=1021 is deliberately ODD, so it is coprime with
# every power-of-two capacity and the deterministic countdown sample
# rotates through all ring positions. It is not 1024.
#
# ONE (cell, session) PER PROCESS: no two cells share an address space.
